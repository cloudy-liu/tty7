## 行为变化

- 若 GUI 启动时复用仍持有 pane 的 daemon，保持只恢复最后聚焦窗口的原有策略，
  其余工作区继续由存活的 daemon 运行。
- 若 daemon 已重建且启用了会话恢复，则恢复此前所有仍处于打开状态的工作区。
  优先显示前台窗口，其余按调度逐个作为可见但不抢焦点的后台窗口打开，并沿用
  各自保存的尺寸和位置。
- 每个窗口使用现有 machine-tree hydration：可附着的 pane 不重复启动 agent；
  缺失的 pane 重新建立，并按保存的准确 ID 恢复自己的 Codex 或 Claude 会话。
  显式本地目录启动不会把路径传给远程工作区；单个窗口恢复失败也不会中断后续恢复。

## 逐提交说明

1. [`256fba55`](https://github.com/cloudy-liu/tty7/commit/256fba55ed6a8b790e410f39a55855ab6d514186)，
   `chore(release): integrate 26.8.3-c.7`。c.7 tag 已在发布分支，但 main 尚缺该段
   历史；通过 cloudy-liu/tty7#31 合入后，文件树仍与 c.7 tag 完全相同。这是补丁
   等价的历史同步，不是新功能。
2. [`f9579f1a`](https://github.com/cloudy-liu/tty7/commit/f9579f1afaad9a904779517efc01acfff0e0db9a)，
   `fix: restore every workspace after daemon replacement`。旧启动流程假定其他工作区
   的 pane 仍由 daemon 持有，daemon 重建后只恢复一个窗口会让其余项目和 agent
   不再运行。现在区分复用与重建，前台优先、后台分批恢复所有此前打开的窗口，
   保留几何位置、本地目录语义和单窗口失败隔离，并复用既有 pane/agent 恢复路径。
   来源：cloudy-liu/tty7#35。
3. [`49b577b3`](https://github.com/cloudy-liu/tty7/commit/49b577b324bfca8b386ee055b5600743dfc0db7a)，
   `fix(daemon): retain reuse when the pidfile is missing`。缺少 `daemon.pid` 时，
   仍存活的 daemon 可能被误判为新建，导致不必要地重开全部窗口。现在依据已持有的
   单例 seat 与启动前即得到的握手判断复用，并对宽限期内才出现的响应保持保守；
   回归测试覆盖这两种时序。来源：cloudy-liu/tty7#35。
4. [`a81c2a88`](https://github.com/cloudy-liu/tty7/commit/a81c2a88099b9bc8bfdf67a5ef250af017323757)，
   `fix(daemon): distinguish late endpoints without a pidfile`。仅凭缺失 PID 后获得的
   握手，仍可能把并发启动的新 daemon 错当旧进程。现在记录启动之初 endpoint 是否
   已存在：预存 endpoint 的成功握手才表明复用，启动过程中出现的 endpoint 仍按
   新进程处理；测试覆盖两种结果。来源：cloudy-liu/tty7#35。
5. [`1d60e43d`](https://github.com/cloudy-liu/tty7/commit/1d60e43d8ce41d15969fa1272e5eac7d1ae437c2)，
   `Merge pull request #35`。将工作区恢复及两笔 daemon 连续性修正合入 fork 的
   main；merge 本身不再增加相对 PR head 的文件变更。来源：cloudy-liu/tty7#35。
6. 本发布提交，`chore(release): prepare 26.8.3-c.8`。workspace 与 Cargo.lock 中
   四个 tty7 包仍是 c.7；统一升级为 c.8，更新中英文 README 和本发布记录，
   使 tag、程序与安装包版本一致。第三方依赖未升级。
