## 行为变化

- 重新启动 agent 前，先把准确的恢复目标存入 server。App 关闭或 server 再次重启后，
  仍能使用同一目标；旧版 server 继续走兼容路径。
- Codex 从原生历史列表打开会话后，server 通过该进程实际打开的会话文件捕获唯一 ID。
  App 窗口关闭期间也会检查，主动停止 server 前再检查一次，无需发送新消息。
- 未输入内容的普通交互式启动会按原参数重新打开。Claude 的初始 `SessionStart`
  可以先分配 ID、后保存历史；这种空会话不会再因恢复不存在的历史而报错。
  终端能力应答不算用户输入。
- 无法确定原会话时，留下可用的 shell，不弹出会话列表，也不猜最近的一段对话。
  Aider 会先在 pane 所在机器检查原历史文件，文件不可用时同样留下 shell。

Cursor、Antigravity `agy` 等没有内置 ID 上报 hook 的 agent，仍需 tty7 已知准确 ID
才能恢复原对话。仅识别到进程不等于已取得会话 ID。对话内容仍由各 agent 自己保存。
更多说明见[会话恢复文档](../agents/sessions.mdx)。

## 逐提交说明

1. [`7e66d9ad`](https://github.com/cloudy-liu/tty7/commit/7e66d9ad531135719895c980b5a0ee23e830c477)，
   `chore(release): prepare 26.8.3-c.6 (#27)`。
   c.6 已从发布分支打 tag，但 main 尚未包含该发布历史。这笔 merge 通过
   cloudy-liu/tty7#27 把 c.6 的版本和文档合入 main。文件树与 c.6 tag 完全相同，
   不是 c.7 的新增功能。
2. [`32008a72`](https://github.com/cloudy-liu/tty7/commit/32008a72f5b3338184e83309482d0d56691757fc)，
   `fix(agents): restore exact sessions after server restarts`。
   仅关闭 App 时仍可使用存活的进程，但 server 重启会暴露未持久化 ID、Codex 未上报
   已选择会话、Claude 空会话尚无历史等缺口。现在先持久化恢复目标，补充 Codex
   打开文件探测，并记录未开始对话的启动状态。Windows hook 按明确的 server 与 pane
   定位控制台；显式恢复 ID 与 Aider 历史路径经过验证，未知会话回到 shell。
   包含重复重启、旧 server 兼容和失败回退的回归测试与文档。
   来源：cloudy-liu/tty7#29。
3. [`3f2aa073`](https://github.com/cloudy-liu/tty7/commit/3f2aa073664fe3d8f36d3fc53f225f3d83eaec04)，
   `test(agents): initialize untouched state in Unix fixtures`。
   新增的未开始标记使 5 处仅在 Unix 编译的测试构造缺少字段。补上 `unstarted: false`，
   恢复 macOS 与 Linux 测试编译，不改变运行时行为。来源：cloudy-liu/tty7#29。
4. 本发布提交，`chore(release): prepare 26.8.3-c.7`。
   workspace 和 Cargo.lock 中四个 tty7 包仍使用 c.6。现在统一升级为 c.7，保证 tag、
   程序与安装包版本一致；更新中英文 README，并加入本发布记录。第三方依赖未升级。
