# Markdown 默认预览与可配置阅读主题

发布目标：`cloudy-liu/tty7` 的 GitHub Issues，标签 `ready-for-agent`。

当前阶段：fork PR 评审与验收。用户已批准在独立 worktree 中实施，并在实现后授权提交、推送和创建 fork PR。范围包括默认 Paperglow 配色、用户主题文件、设置选择、动态加载，以及本文列出的 Markdown 和 README 兼容能力。用户已确认 Markdown 预览范围和两处测试入口；验证结果及尚待人工验收的项目记录在 [实现验证记录](../testing/markdown-preview.md)。

## Problem Statement

用户打开 Markdown 是为了阅读，但 tty7 目前先显示源码，需要再点击“预览”。预览使用通用文本组件的默认样式，正文、标题、引用、链接和代码缺少一致的阅读配色，标题层级和留白也不够清楚。

用户已经选定 Paperglow for Typora 的浅色和深色主题，希望把两套阅读样式移植为 tty7 的默认 Markdown 预览。浅色界面自动使用 Paperglow 浅色，深色界面自动使用 Paperglow Dark，无需初次配置。以后用户也希望把其他 Markdown 主题文件放入指定目录，再从设置中选择，换主题时不必修改 Rust 代码或重新编译。

Markdown 阅读主题需要独立于 tty7 的应用主题选择。用户选择一套阅读主题后，由应用实际生效的深浅模式决定使用其中的哪个变体，不必分别维护两个阅读主题选项。

现有实现还存在与此次改造直接相关的问题：文件打开后会把焦点交给源码输入框；Markdown 预览没有启用文本选择；GitHub 提示块没有专门显示；README 常用 HTML 和相对资源缺少完整处理。默认打开预览后，这些行为必须一起明确，避免出现隐藏编辑、内容缺失或资源来自错误主机的问题。

## Solution

普通打开受支持的 Markdown 文件时，直接显示 Paperglow 预览，并在状态栏提供“编辑”入口。用户切换到源码后可以继续编辑、保存，再通过“预览”查看当前缓冲区的内容。切换文件、阅读主题和显示模式时，文档状态持续保留。

提供声明式 Markdown 主题包。每个包用一个 YAML 文件描述共用排版、浅色配色和深色配色，Paperglow 作为内置默认包。内置包与用户包通过同一套解析、校验和样式解析接口进入原生渲染器；运行时加载主题数据。

设置的外观页增加“Markdown 阅读主题”下拉选择和“打开主题目录”入口。用户放入有效主题文件后即可选择，选择持久保存；修改当前主题文件后，已打开的预览自动更新。文件无效时在设置中显示具体错误，并保留当前主题最近一次有效的内容。

选色依据是 tty7 当前实际生效的深浅模式，覆盖手动选应用主题、自定义应用主题、跟随系统，以及应用主题选择器的临时预览和取消。主题首屏即正确，切换后立即更新正文和代码高亮。

继续使用 GPUI 原生 Markdown 渲染。移植内容包括阅读背景、正文、标题、链接、行内代码、代码块、引用、提示块、列表和表格；宽阅读区保留居中纸张布局，窄分栏收紧留白。补齐本规格列出的常用 Markdown、README HTML 和同主机相对资源显示。

## User Stories

1. 作为 Markdown 读者，我希望新打开的 Markdown 文件立即显示渲染后的内容，以便直接阅读，无需点击“预览”。
2. 作为 Markdown 读者，我希望两种受支持的 Markdown 扩展名都能识别且不区分大小写，以便文件命名方式不影响打开行为。
3. 作为本地工作区用户，我希望文件树条目和普通文件链接采用相同的打开策略，以便从不同入口打开文档时得到一致的结果。
4. 作为远程工作区用户，我希望通过 SSH 和 SFTP 打开的 Markdown 文件也默认预览，以便无论文档位于哪台主机都能直接阅读。
5. 作为文档作者，我希望预览中提供“编辑”入口，以便直接切换到源码缓冲区。
6. 作为文档作者，我希望预览渲染当前尚未保存的缓冲区内容，以便在保存前检查修改效果。
7. 作为文档作者，我希望切换模式时保留撤销历史、未保存状态和保存冲突处理，以便阅读过程不会丢失我的修改。
8. 作为继续阅读的用户，我希望每个已打开文档保留当前模式和阅读位置，以便切换文件后能接着读。
9. 作为通过行列号链接定位内容的开发者，我希望源码编辑器显示指定位置，以便从诊断信息直接跳到相关文本。
10. 作为浅色主题用户，我希望文档从首个渲染帧就使用所选阅读主题的浅色变体，默认采用 Paperglow，以便打开后立即获得可读的内容。
11. 作为深色主题用户，我希望文档从首个渲染帧就使用所选阅读主题的深色变体，默认采用 Paperglow Dark，以便预览符合当前阅读环境。
12. 作为切换应用主题的用户，我希望已打开文档及其语法高亮颜色一起更新，以便无需重新打开文件。
13. 作为跟随系统外观的用户，我希望 Markdown 跟随应用实际生效的外观，以便我配置的深浅预设继续决定显示效果。
14. 作为自定义主题用户，我希望阅读配色依据主题实际的深浅模式选择，以便主题名称不会导致选错颜色。
15. 作为在主题选择器中试用主题的用户，我希望取消临时预览时也恢复 Markdown 配色，以便文档与应用界面保持一致。
16. 作为读者，我希望标题层级清晰、段落间距一致，以便快速浏览长文档。
17. 作为中英文内容的读者，我希望使用合适的离线字体回退并正确缩放，以便文字在我的系统上保持清晰可读。
18. 作为在窄文档列中阅读的用户，我希望留白随该列宽度调整，以便装饰不会挤占阅读空间。
19. 作为代码读者，我希望行内代码和围栏代码块有各自清晰的配色，以便区分代码与正文。
20. 作为阅读语法高亮代码的用户，我希望语法颜色采用所选阅读主题的配色，默认采用 Paperglow，未知语言也能正常显示，以便每个代码块都可读。
21. 作为阅读长代码和宽表格的用户，我希望这些区块能各自横向滚动，以便整篇文档不会横向溢出。
22. 作为列表和表格的读者，我希望嵌套关系、任务状态、对齐和表头清楚呈现，以便格式准确传达内容含义。
23. 作为引用内容的读者，我希望普通引用和 GitHub 提示块有各自清晰的呈现方式，以便原始提示标记不会干扰阅读。
24. 作为 README 读者，我希望受支持的居中 HTML、图片和链接能够渲染，以便正常理解介绍内容和徽章信息。
25. 作为仓库文档读者，我希望相对图片和文件链接从文档所属主机及目录解析，以便本地和远程文档都加载正确的资源。
26. 作为通过文档链接导航的读者，我希望标题锚点和外部网页链接能够到达目标，以便在预览中继续使用这些链接。
27. 作为读者，我希望可以选择并复制正文和代码，以便无需切换到源码就能复用内容。
28. 作为键盘用户，我希望阅读时由预览持有焦点，以便输入或粘贴不会修改不可见的源码编辑器。
29. 作为阅读持续变化文件的用户，我希望现有重载和冲突规则继续生效，以便显示内容与我的编辑状态保持一致。
30. 作为遇到图片缺失或文档无效的读者，我希望仍有可读的降级显示和源码入口，以便单个错误不会隐藏整个文件。
31. 作为使用 tty7 其他视图的用户，我希望 Markdown 阅读配色只作用于其预览，以便当前主题的其他部分保持原有外观。
32. 作为维护者，我希望依赖版本固定且可移植、来源署名完整，并有聚焦行为的测试，以便其他开发者也能构建和维护此功能。
33. 作为初次使用的读者，我希望不安装或选择任何主题就能使用 Paperglow，以便直接阅读文档。
34. 作为希望更换阅读样式的用户，我希望把一个主题文件放入专用目录后，它自动出现在设置中，以便无需修改程序即可安装主题。
35. 作为设置使用者，我希望能从外观页选择 Markdown 阅读主题并打开主题目录，以便找到更换主题的入口。
36. 作为再次启动应用的用户，我希望保留上次选择的阅读主题，以便每次打开文档都有一致的样式。
37. 作为同时调整应用与阅读外观的用户，我希望两者分别保存选择，阅读主题只跟随应用的深浅模式，以便更换应用配色时保留喜欢的阅读样式。
38. 作为主题作者，我希望在一个文件中配置字体、排版、各阅读元素和代码高亮的深浅配色，以便制作完整的阅读主题。
39. 作为主题作者，我希望可以只覆盖需要修改的样式，其余使用明确的默认值，以便从小范围修改开始制作主题。
40. 作为正在调试主题的用户，我希望保存主题文件后已打开的预览自动刷新，并保留内容和阅读状态，以便连续查看效果。
41. 作为写错主题配置的用户，我希望设置指出出错的文件与字段，并保留最近有效的阅读效果，以便修复过程中仍可读文档。
42. 作为移除或迁移主题文件的用户，我希望主题不可用时有明确提示和可读的默认回退，以便应用仍能启动和显示文档。
43. 作为指定自定义配置目录的用户，我希望主题发现和打开目录都跟随该配置目录，以便不同配置环境互不混用。
44. 作为拥有多个主题文件的用户，我希望重名、重复标识或不受支持的版本得到确定的处理结果，以便文件遍历顺序不会改变实际使用的主题。
45. 作为迁移 Typora 主题的用户，我希望知道 tty7 接受的主题格式、支持的样式以及转换示例，以便判断如何迁移已有 CSS 配色。

## Implementation Decisions

### 1. 文件打开与模式切换

复用现有文件语言识别，首轮支持 `.md` 和 `.markdown`，扩展名大小写不敏感。所有打开入口共享同一策略，文件树、本地文件链接、远程工作区和 SFTP 不各自实现一份规则。

| 场景 | 目标行为 |
|---|---|
| 普通打开一个新的 Markdown 文档 | 默认预览，操作入口显示“编辑” |
| 普通打开一个新的非 Markdown 文件 | 使用现有源码编辑模式 |
| 再次激活已经打开的文档 | 保留该文档当前模式和状态 |
| 在 Markdown 预览中选择“编辑” | 显示同一个源码缓冲区并把焦点交给编辑器 |
| 在源码中选择“预览” | 渲染当前缓冲区并把焦点交给阅读区 |
| 打开明确指定行号或行列号的链接 | 进入源码并显示目标位置，包括已经打开的 Markdown |
| 关闭后重新普通打开 Markdown | 重新应用默认预览策略 |
| 文件读取失败或被现有大小、编码检查拒绝 | 使用现有错误反馈，不构造空白的成功预览 |

“默认预览”在新文档进入编辑器时决定，不能在每次重绘、激活或主题切换时强制覆盖用户选择。首轮不增加默认打开模式开关，也不保存跨应用重启的文档模式偏好；阅读主题选择单独持久保存。

文档继续以所属主机和规范化路径区分。源码缓冲区是内容的唯一来源；预览不另建可编辑副本，也不为了切换模式重新读取磁盘。预览必须反映未保存内容，模式和主题切换不触发保存、不增加脏标记、不清空撤销历史。

每个 Markdown 文档持有一个持续存在的预览状态，包含解析结果、选择、阅读焦点和滚动状态。切换文档或配色时复用该状态，不能让不同文档共享同一个临时渲染标识。

源码光标、源码滚动和预览滚动分别保留。内容变短时允许把滚动位置限制到有效范围；纯配色切换不能使阅读位置回到顶部。主题改动字号或版式时会重新布局，尽量保留可见段落及段内偏移，无法继续定位时限制到有效阅读位置。相同路径位于不同主机时，内容、模式、选择和资源缓存均须隔离。

### 2. 焦点与阅读操作

把当前“聚焦源码输入框”的单一路径改为按当前文档模式聚焦。新文档打开、重新激活、显示文档列和模式切换都使用这条路径。

预览获得阅读和选择焦点，支持现有平台约定的复制、全选和滚动操作。普通输入、粘贴、删除以及撤销动作不能修改隐藏的源码缓冲区，也不能误发到后面的终端。源码编辑模式继续使用原有编辑快捷键。

启用正文选择，并为代码块提供复制入口。代码复制返回原始代码内容，不混入语言名、按钮标签或视觉装饰。任务列表的复选框在预览中展示状态，不通过点击修改文档。

状态栏复用现有“编辑 / 预览”文案与本地化机制。行列号、换行和查找替换等源码专属操作只在适用的模式下显示或启用。已有未保存提示、保存和关闭确认继续围绕同一缓冲区工作。

### 3. 主题包、设置与动态加载

#### 3.1 主题文件格式

第一版采用声明式主题包，一个包对应一个 UTF-8 YAML 文件，同时接受大小写不敏感的 `.yaml` 和 `.yml` 扩展名。一个包必须声明浅色和深色两个变体，排版参数共用。这样用户只需选择一次阅读主题，切换应用模式时仍有对应配色。

| 字段或样式组 | 约定 |
|---|---|
| `schema_version` | 必填，第一版为 1；不支持的版本拒绝加载并提示 |
| `id` | 必填、非空的稳定小写 ASCII 标识，可含数字、连字符和下划线；内置 `paperglow` 标识保留 |
| `name` | 必填、非空的显示名称，允许中文；同名但不同 ID 的主题在设置中显示 ID 以区分 |
| `author`、`description`、`license` | 可选的署名、说明和许可信息，仅作为数据展示 |
| `typography` | 可选的字体回退列表、正文和代码字号、行高、六级标题字号与字重、段落和标题间距 |
| `layout` | 可选的阅读宽度、宽窄分栏断点、内外边距、圆角、边线、阴影及代码、引用、列表和表格间距 |
| `light`、`dark` | 两个必填映射，分别包含阅读语义颜色与代码语法颜色；允许只覆盖其中部分字段 |

语义颜色覆盖本规格中的背景、纸张、正文、标题、次要文字、链接及悬停、选择、行内代码、代码块、引用、嵌套引用、提示块、列表、表格和分隔线。代码语法颜色按现有高亮器支持的语义分类配置。第一版提供一份包含全部可用字段的主题示例，避免要求用户从组件代码猜测格式。

内置 Paperglow 文件给出完整默认值。用户包中省略的排版或颜色字段从内置默认值补齐，浅色和深色分别补齐；缺少整个变体则拒绝加载，不自动反色。第一版只提供这一个固定默认来源，不支持主题间继承链。正文、标题和代码字体可按主题指定本机字体列表，代码字体未指定时沿用应用配置的等宽字体。

加载时校验字段名、类型、版本、标识及数值范围。未知字段报错，避免拼写错误被忽略；颜色接受六位或八位十六进制及 RGBA 表示，颜色分量和透明度必须有效。字号、行高、阅读宽度及分栏断点使用有限正数，边距和圆角等允许为零的量不得为负。字体不存在时使用离线回退，不判为主题加载失败。

这套格式表达 GPUI 支持的阅读样式，不包含 CSS 选择器、脚本、可执行插件入口或在线资源加载指令。Paperglow 的 Typora CSS 在移植时转换为该格式；其他 Typora CSS 也需要转换。增加主题只改数据；增加渲染器尚不支持的新样式能力仍需修改程序并维护格式版本。

#### 3.2 目录与主题注册表

用户主题放在当前有效配置目录下名为 `markdown-themes` 的专用目录中，遵循现有 `--config-dir` 选择。读取本机的应用配置目录，文档位于 SSH 或 SFTP 主机时也使用同一阅读主题。首轮只发现该目录直接包含的 YAML 文件，不混入应用主题目录，也不加载任意压缩包或远程主题地址。

内置 Paperglow 随应用打包，不要求配置目录存在对应文件。内置和用户文件共用主题解析、校验和样式解析接口；用户目录中的文件不能覆盖内置标识。设置按稳定顺序显示可用主题，标明内置或用户来源。

主题注册表负责发现文件、补全默认值、校验、记录来源与错误，并发布不可变的有效主题快照。应用主题现有文件结构要求终端 ANSI 配色，Markdown 使用独立结构；复用目录定位、文件监听和设置交互机制，避免重构全部主题系统。

多个用户文件声明相同 ID 时，这些冲突文件均不可作为新的有效候选，在设置中列出冲突来源。结果不依赖文件遍历顺序。文件重命名但 ID 不变时保留选择；修改 ID 按删除旧包和新增包处理。

#### 3.3 设置、持久化与深浅解析

现有用户配置增加 `markdown_theme` 字符串字段，保存包 ID，缺省为 `paperglow`。旧配置不需要迁移；不把本机主题文件绝对路径或主题全部内容写入用户配置。

设置的外观页增加“Markdown 阅读主题”下拉选择、“打开主题目录”和加载错误信息。打开目录时按需创建目录，并使用现有系统文件管理器入口；失败时显示实际错误。有效选择确认后立即应用，并通过现有配置写入机制保存。取消选择不改配置，新增文件也不会自动抢占当前选择。错误文件列在错误信息中，不作为可选的新主题。

阅读主题选择与应用主题选择各自独立。解析顺序固定为：读取所选阅读主题包，再读取 tty7 已解析并实际应用的 Light 或 Dark 模式，最后生成该变体的完整局部样式。不能通过预设名称、操作系统状态的单独读数或终端背景色重新猜测模式。

主题跟随包括手动切换应用主题、跟随系统、自定义应用主题、应用主题选择器临时预览及取消恢复。首次布局使用正确主题；所有已打开预览响应选择、模式和主题文件变化，隐藏的预览在再次显示时使用最新样式。跨窗口更新沿用现有全局配置通知。

阅读配色只传给 Markdown 实例。正文、链接、选择、表格、引用和代码高亮使用同一份解析结果。组件接收完整样式值，不读取用户主题目录，也不判断 Paperglow 或其他包名称。

#### 3.4 热加载与失败规则

扩展现有配置目录监听，复用其 200ms 防抖，识别主题目录的创建、文件新增、写入、删除和重命名。解析与校验在 UI 线程之外完成；两套变体都成功后才一次性发布新快照，部分写入或单个无效文件不能破坏其他主题。加载请求带修订号，过期加载结果不能覆盖较新请求的结果。

| 情况 | 行为 |
|---|---|
| 未配置阅读主题或选择内置主题 | 使用内置 Paperglow 的实际深浅变体 |
| 新增一个有效主题文件 | 自动出现在设置中，当前选择不变 |
| 修改当前主题且校验成功 | 自动应用完整新版本，所有打开文档使用新样式 |
| 修改当前主题但校验失败 | 本次运行继续使用该 ID 最近成功加载的完整包，在设置中显示文件和字段错误 |
| 删除当前主题或使其 ID 冲突 | 本次运行保留该 ID 最近有效的完整包，设置标明不可用；修复后自动恢复正常加载 |
| 启动或选择时找不到有效包，且没有该 ID 的内存快照 | 回退内置 Paperglow，保留配置中的目标 ID，并显示回退原因 |
| 修复或重新放回配置指向的主题 | 自动恢复使用该包，不要求重新选择 |
| 无效或删除的主题并非当前主题 | 从可选列表移除对应无效候选，当前文档不变；解析错误独立展示 |
| 保存后样式内容没有改变 | 不增加有效样式修订，不重建文档解析结果 |

最近有效包只在本次运行中保留，不新增持久化主题缓存。回退和错误恢复不擅自改写用户选择；用户主动选择另一个有效主题时正常持久化新 ID。设置同时显示配置目标、当前实际使用的主题和错误，避免回退无提示。

有效样式身份包括主题 ID、深浅变体和成功加载后的样式修订。高亮缓存据此失效，同名主题文件只改一个语法颜色也必须刷新。配色更新保留文档实体、内容解析和阅读位置；排版更新仅重新布局并恢复合理阅读位置，不重读文件或改动源码缓冲区。

### 5. 排版与分栏适配

以下尺寸是内置 Paperglow 在应用缩放为 100% 时的逻辑像素基准，实际显示统一遵循应用缩放和系统 DPI。用户主题可通过受支持的排版字段调整这些参数，渲染器不按主题名称硬编码尺寸。

| 元素 | 基准 |
|---|---|
| 正文 | 17px，常规字重，1.5 倍行高；段落间距约一个正文字号 |
| 一级标题 | 32px，字重 700 |
| 二级标题 | 27px，字重 600，底部细分隔线 |
| 三级标题 | 23px，字重 500 |
| 四、五、六级标题 | 20px、18px、17px，字重 500 |
| 标题节奏 | 1.4 倍行高；章节标题保留上方留白，文档开头不额外堆叠顶距 |
| 代码块 | 14px 等宽字体，独立底色和边线，圆角 16px，内边距约 16px / 20px |
| 普通引用 | 3px 左边线，右侧圆角 8px，独立背景；嵌套引用使用来源中的第二层颜色 |
| 表格 | 表头字重 600，横向细分隔线，单元格约 8px 纵向留白；保留 Markdown 对齐语义 |

正文与标题优先使用 Montserrat，再使用系统无衬线及中文字体回退；中文覆盖 Noto Sans SC、PingFang SC、Microsoft YaHei 等可用字体。代码沿用应用配置的等宽字体与离线回退。字体缺失时仍正常显示，运行时不请求 Google Fonts；首轮不以新增字体分发为前提。字体回退造成的字形差异需在视觉验收中记录。

布局依据 Markdown 阅读区自身宽度，不能依据整扇窗口的宽度。内置 Paperglow 的基准方案如下，实施中只对间距做视觉微调，不改变其深浅配色或默认打开行为：

- 阅读区宽度至少 800px 时，正文卡片居中，最大总宽度 1100px，外围约 24px 留白，卡片左右内边距约 48px，保留细边线、16px 圆角和淡阴影。
- 阅读区小于 800px 时，收起外围纸张留白，正文左右内边距收至 16 至 24px，减少边框和阴影占用；更窄的可用区域允许收至 12px。
- 长代码块和宽表格分别横向滚动，正文继续在阅读区内换行。图片按可用宽度等比缩小，尺寸未知或加载失败时保留可读占位。
- 使用既有文档列和滚动条约定，兼容停靠、提升显示和填满工作区的布局。

### 6. Markdown 与 README 兼容范围

保留常规 GFM 行为，包括标题、段落、强调、删除线、有序和无序列表、嵌套列表、任务列表、引用、分割线、代码、表格和链接。普通软换行遵循 Markdown 文本流规则，明确硬换行和受支持的 HTML 换行保留换行效果。

识别引用块开头的 GitHub `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 提示标记，显示名称、图标和正文。提示块使用当前阅读主题提供的样式，内置 Paperglow 采用统一暖色提示块；普通引用保持普通引用样式。代码示例、正文中间或不完整标记不能被误识别为提示块。

README HTML 首轮支持段落和容器的左右或居中对齐、换行、图片的替代文本及宽高、链接和常见行内强调。以 `p`、`div`、`br`、`img`、`a`、`strong`、`b`、`em`、`i`、`code`、`kbd` 的展示子集为边界。支持范围外的内容保留可读文本或原始片段；不执行脚本、事件属性或任意网页样式。

相对图片与文件链接以当前文档所在主机及父目录解析。资源读取通过已有 Host 抽象执行，远程路径不会被当成本机路径读取。资源缓存同时包含主机身份，异步结果只能回到发起它的文档。

HTTP 和 HTTPS 图片沿用应用资源加载能力；失败时显示替代文本或占位，正文仍能阅读。HTTP 和 HTTPS 链接使用已有浏览器打开行为；同主机文档链接复用文件打开策略。文内标题锚点在当前预览中定位，标题 ID 稳定，重复标题可区分。无效目标不应打开错误的本地文件。

### 7. 模块职责与依赖交付

| 模块边界 | 职责 |
|---|---|
| 文档打开与状态管理 | 初始模式、明确源码定位、模式切换、焦点、缓冲区和阅读位置 |
| Markdown 主题格式与注册表 | 内置和用户包的发现、解析、默认值补全、校验、来源、错误和有效修订 |
| Markdown 主题解析与设置接入 | 保存包 ID，结合实际深浅模式解析完整样式，处理回退、热加载与窗口通知 |
| tty7 Markdown 阅读视图 | 每篇文档持续存在的预览状态、内容修订同步、局部样式应用、响应宽度、提示块和复制 |
| 通用原生文本组件 | 按实例提供链接、行内代码、标题、引用、表格、分割线和高亮样式；资源及链接扩展入口 |
| 文档资源适配 | 把相对地址接入文档持有的 Host，管理异步加载和缓存身份 |

数据流是主题文件进入注册表，注册表结合配置选择和实际深浅模式生成完整样式，阅读视图再把样式传给通用组件。源码内容通过独立的缓冲区修订进入同一阅读视图，换主题不进入文件读取、编辑或保存流程。

通用组件保留原来的默认行为；只有 Markdown 阅读实例主动传入所选阅读主题。组件不得依赖 tty7 的业务配置、主机注册表或主题名称。已有 Markdown 扩展机制优先用于提示块等展示扩展，扩展在稳定的初始化边界注册，避免每次重绘更新扩展版本并触发全文重解析。

补齐组件对外的阅读焦点接口，让应用能按模式聚焦并识别当前文档的保存、关闭操作。样式接口覆盖全部受支持的阅读元素，并区分需要重新布局的参数与纯配色参数。

现有样式比较没有覆盖全部可变样式，代码高亮又在解析阶段保存了主题。因此组件修改必须同时处理样式失效和高亮失效，保证内容没有变化时也能正确切换配色。代码块显示时使用当前实例的高亮配置，不继续读取解析时保存的旧主题。不能通过暂时修改全局主题来实现局部渲染，也不能依赖反复销毁阅读视图来更新颜色。

组件修改以 tty7 原先锁定的 `l0ng-ai/gpui-component` 定制版本为基线，保留现有定制并补充通用接口。现已建立 [cloudy-liu/gpui-component](https://github.com/cloudy-liu/gpui-component) 维护 fork，组件与资源包固定到 [2ebbed0674739b5fc56f71bef1b4a436b08321e7](https://github.com/cloudy-liu/gpui-component/commit/2ebbed0674739b5fc56f71bef1b4a436b08321e7)。

开发时可以协同修改组件，最终交付必须能从干净 checkout 构建。组件库与组件资源包固定到同一个维护 fork 的同一提交，避免混用来源造成资源包或原生链接冲突。不得依赖本机 Cargo 缓存修改或不可移植的临时目录引用；锁文件和依赖来源一并验证。tty7 的集成 PR 目标为 `cloudy-liu/tty7:main`。组件评审见 [cloudy-liu/gpui-component#1](https://github.com/cloudy-liu/gpui-component/pull/1)，目标为该 fork 既有的 `tty7` 定制分支。两个 PR 保留尚待人工及跨平台验收的项目。

### 8. 失败处理、性能与内容一致性

沿用现有 4 MiB 文档大小上限，以及二进制和 UTF-8 检查。空 Markdown 展示空阅读区并保留“编辑”入口。解析失败时保留源码缓冲区和编辑入口，不能让未保存内容消失。

解析按文档内容修订复用；编辑后在预览需要显示时同步最新缓冲区，不在每次重绘中复制或解析全文。滚动、切换主题包、深浅变化和主题文件重载均不改变内容修订。配色更新局部样式及高亮，排版更新布局，两者都不重新读取文件。图片和远程资源异步加载，设置有界读取与缓存，关闭文档或资源失败不阻塞其余阅读操作。

主题加载和文档解析是独立的失败边界。主题格式错误走主题回退规则，不显示为文档解析失败，也不能清空有效文档。文档尚在编辑时收到主题更新，只更新阅读配置，不能切换模式或修改编辑状态。

外部文件更新继续使用现有重载和冲突判定。干净缓冲区更新后，预览显示新内容；有未保存编辑时继续提示冲突，保留用户编辑。此项验证复用已有保存和外部变更测试，不重新设计文件监听或保存系统。

## Testing Decisions

### 测试边界

用户已确认应用阅读流程和通用渲染组件这两处测试入口，并保留深浅主题视觉验收。

主要测试入口放在文档阅读流程：打开属于某个 Host 的文件，观察显示模式与可见内容，执行编辑、设置选择、应用深浅切换或主题文件修改，再观察内容、焦点、复制结果和保存状态。复用现有 GPUI 应用测试窗口、文档 overlay 测试方式，以及现有文件状态测试；不只测试一个默认布尔值。

第二个必要边界是通用 `TextView` 的公开行为，因为局部样式、高亮失效和 Markdown 扩展要跨仓库交付。仅为这些组件能力补充测试，不为每个颜色常量、内部构造步骤或每个 Markdown 元素再建立独立测试层。

优先采用用户可见结果作为断言。需要模拟的对象限定为文件或网络 I/O 等外部边界；不要 mock 整个渲染器、主题选择器或当前缓冲区来制造通过结果。配色常量表和实现相互抄写的断言不作为完成证据。

主题文件用临时配置目录中的实际 YAML 样例驱动应用流程，覆盖发现、校验、选择、持久化、热加载和错误恢复。沿用现有文件事件与配置重载入口注入确定的变更信号，避免依赖任意时长的等待；实际操作系统文件监听另通过 UI 验收确认。

### 自动化覆盖

| 覆盖组 | 关键观察结果 |
|---|---|
| 打开策略 | 两种扩展名及大小写、新文档与已打开文档、非 Markdown、带行列号跳转各自进入规定模式 |
| 缓冲区往返 | 修改但不保存后切到预览，看到新内容；切回编辑后撤销、光标、脏标记仍正确；未发生额外磁盘写入 |
| 焦点和动作 | 初次预览及再次激活时，输入或粘贴不改源码；编辑后可输入；选择复制来自当前阅读区 |
| 主题跟随 | 手动、系统、自定义主题，以及临时预览和取消都使用实际模式；首次和动态更新的正文、高亮一致 |
| 主题安装与持久化 | 无配置时使用 Paperglow；放入有效包后设置可选，选中后全部预览更新，重新加载配置仍保留选择；自定义配置目录正确隔离 |
| 主题格式与错误 | 缺项按同模式默认值补齐；缺变体、未知字段、非法颜色、无效尺寸、版本不支持和重复 ID 显示具体错误，其他主题仍可用 |
| 热加载与恢复 | 选中主题改色或改排版后刷新；损坏、删除和冲突保留最近有效包；启动时不可用则回退，修复后恢复；相同 ID 下高亮颜色也会更新 |
| 事件与修订 | 文件重命名保持 ID 时保留选择；新包不会抢占选择；过期加载结果不能覆盖新结果，无实际样式变化时不重建文档 |
| 局部隔离 | 同一窗口中使用默认样式的文本组件及源码编辑器不受 Markdown 的局部配置影响 |
| 文档状态 | 文件切换和主题切换保留模式及合理滚动位置，不同主机相同路径不串内容或资源 |
| Markdown 行为 | 常用元素、五种提示块、误识别反例、未知代码语言、软硬换行和支持的 HTML 展示子集 |
| 资源与导航 | 相对地址基于正确父目录和 Host；标题锚点、文档链接、资源失败及过期异步结果处理正确 |
| 原有保护 | 空文件、大小与编码拒绝、干净文件重载、有编辑时的冲突和源码可恢复 |

主题解析的既有 GPUI 测试、语言识别测试、保存与外部变更测试，以及组件的内联图片、选择和代码块测试继续复用。新增应用阅读测试采用现有 GPUI 测试窗口和空终端 pane，可在 Windows 直接验证真实文档打开、编辑、主题与资源流程，无需扩建终端测试框架。SSH/SFTP 的真实连接和操作系统文件监听仍需集成验收。

### 视觉与交互验收

使用同一份包含中英文、六级标题、链接、选择、代码、嵌套列表、任务项、引用、五种提示块、宽表、图片和 HTML 的样例，再对照 tty7 README 的实际内容。

- 两套主题分别检查宽阅读区和窄分栏，确认主要颜色来自上述基准，标题层级、背景、代码、引用和表格一致。
- 在 Windows 100%、125%、150%、200% DPI 下抽样验证；应用字号或缩放变化与 DPI 分开检查，不出现文字裁切或重复放大。
- 深浅切换、主题选择器取消、切换文件和编辑往返后，检查阅读位置、代码高亮、选择复制及键盘焦点。
- 通过设置打开主题目录，放入另一个有明显配色和排版差异的完整样例，确认可选择、持久化和自动刷新；检查改错、删除、修复及重启回退提示。
- 长代码和宽表只在自己的区域横向滚动；正文、图片和文档列没有意外的整体横向溢出。
- 本地、SSH 和 SFTP 各验证一次默认预览及相对资源；关闭文档后到达的资源结果不能写入另一篇文档。
- 检查大于常规 README 的长文档和接近既有大小上限的样例，记录首次显示与连续滚动表现；不能出现反复全文解析导致的持续卡顿。

图片对照采用固定样例和固定窗口条件，同时记录实际使用的字体。自动化行为测试通过不能代替阅读样式的视觉验收。

## Out of Scope

- 修改 tty7 的应用默认主题、终端 ANSI 配色或源码编辑器主题。

- 引入 WebView、执行任意 HTML/CSS/JavaScript、MDX 执行或所见即所得编辑。
